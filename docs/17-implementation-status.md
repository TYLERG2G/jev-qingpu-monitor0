# 17 實作狀態（v0.6）

> 2026-10-18，依 D-018 實作並自行測試；同日依使用者「先把完整功能做好再測試」補齊社區總覽、JEV 決策模型、通知規則、地基修正（D-020、D-113）。本文件只記錄**實際執行過**的結果。使用方式見 [18 使用手冊](18-user-guide.md)。
> 範圍限制：不執行爬蟲、不自動擷取任何平台、不部署到外部；刊登資料只來自人工記錄（含使用者觸發的單頁書籤匯入，D-019）與官方開放資料。對外連線只有使用者自行設定並同意的三種：SMTP、Telegram、決策模型。

## 1. 結論
| 目標 | 狀態 | 說明 |
|------|------|------|
| 社區總覽 | **可用** | 各棟各戶、刊登落在哪一戶、開價行情、官方成交、推導規則、缺口與下一步（依對門牌準確度的幫助排序） |
| 1. 房源監控 | **可用（人工記錄模式）** | CSV、API 或 591 書籤匯入；新刊登、降價、欄位變動、下架、重新上架；可自訂通知規則（門檻、Email／Telegram） |
| 2. 跨刊登同屋辨識 | **可用** | 配對計分、衝突、覆核、合併／拆分／撤回、更正通知；不自動合併 |
| 3. 完整門牌推斷 | **可用** | 坪數、樓層、戶別、方位、該層戶數 → 戶別 × 樓層候選與依據；人工佐證 H1–H6；名冊驗證後 K1–K5 |
| JEV 決策模型（D-020） | **已實作，尚未用真實模型測試** | OpenAI、OpenRouter、TypeSafe 三種 provider；窗景前後排（S13）、樓層高低（S14）、社區文字（M9m）、同一戶（P9m）；只做軟計分；評估工具已備好。測試都用假的傳輸層，**沒有呼叫過任何外部模型**（使用者要求先做功能、之後再測） |

**目前資料下的實際結果**（13 則真實人工記錄＋1 次書籤匯入）：全部屬於聯上世界；2 則戶別唯一（C3）；5 則縮小到 2 個完整門牌候選；**0 則門牌已確認**（戶別→門牌號對照沒有獨立佐證，依規則不會自行確認）。

## 2. 如何執行
見 [18 使用手冊](18-user-guide.md)。重點：
```powershell
$py = "C:\Users\als14\anaconda3\python.exe"
& $py -m jev serve          # http://127.0.0.1:8787/（金鑰自動產生並帶入；啟動前自動備份）
& $py -m jev config         # 檢查 .env 設定（金鑰遮蔽、不連網）
& $py -m pytest -q          # 109 個測試
```
需求：Anaconda base 的 Python 3.13。執行期只用標準函式庫；測試需要 pytest、PyYAML、jsonschema（Anaconda 內建）。前端解析器的測試需要 Node.js（沒有時自動略過）。

### 2.1 人工記錄 CSV 欄位
| 欄位 | 必填 | 說明 |
|------|------|------|
| `source_code` | 是 | `SRC-591`、`SRC-SINYI`、`SRC-YUNGCHING`、`SRC-LEJU`、`SRC-MANUAL` |
| `external_id` 或 `url` | 平台來源必填 | 平台的刊登編號；只有網址時用網址雜湊 |
| `total_price` | 是 | 元，整數 |
| `observed_at` | 建議 | 觀測時間（ISO 8601） |
| `building_ping`、`parking_ping`、`main_ping`、`parking_included` | 建議 | `INCLUDED`（坪數含車位，591 的標示方式）、`EXCLUDED`、`UNKNOWN`（雙口徑試算） |
| `floor_text` | 建議 | `12樓/14樓`、`10~15樓`、`中樓層` |
| `rooms`、`halls`、`baths`、`orientation`、`units_per_floor`、`sales_unit_text` | 選填 | 縮小戶別用 |
| `community_text`、`platform_community_ref`、`address_text`、`map_address`、`title` | 選填 | 社區歸屬用 |
| `lister_type`、`lister_company` | 選填 | 只記公司層級；不記錄個人聯絡資料 |
| `is_new_listing` | 選填 | `true` = 你確認是新上架（INCREMENTAL 才有效） |

任何一列有錯，整個檔案都不寫入，並回報第幾列；匯入前自動備份。

### 2.2 591 一鍵匯入（書籤，D-019）
`http://127.0.0.1:8787/tools` 安裝書籤 → 在 591 刊登頁按書籤 → 核對 → 寫入。解析規則 `jev/ui/parse591.js`：總價、坪數、地址取自 JSON-LD；樓層、格局、車位取自畫面文字；社區以「位於○○」為準，不採用「熱門社區」推薦連結。只取房屋欄位。已用 M0 的 2 則樣本頁、Edge 引擎與 1 次真實匯入（20970583）驗證。

## 3. 實作範圍
- 程式：`jev/`（約 4,400 行，標準函式庫）；介面：`jev/ui/index.html`、`jev/ui/parse591.js`（約 700 行，不連外部資源）。
- 資料庫：SQLite，`schema_version` 5；啟動時自動備份並補上新增欄位（相容變更）；需要非相容變更時會停止並提示。
- API：只接受 127.0.0.1／localhost（Host 檢查）；`X-API-Key`（沒設定 `JEV_API_KEY` 時自動產生，存在 `data\api_key.txt`）；`Idempotency-Key`、`If-Match`、RFC 9457；所有錯誤都回 problem 並寫入 `data\logs\jev.log`；每個寫入請求是一個交易（失敗時整個還原）。
- **契約 66 個操作中實作 51 個**（v0.6 新增：社區總覽、決策模型 5 個、通知規則新增／修改／刪除、匯出、名冊讀取、新觀測）。未實作的回 405 problem：

| 未實作的操作 | 理由 |
|--------------|------|
| `GET/POST /sources/{id}/runs`、`PATCH /sources/{id}` | 自動擷取不在範圍內 |
| `POST /listings:import`、`POST /registry:import` | CLI 已提供 |
| `PATCH /listings/{id}` | 新的觀測用匯入或 `POST /listings/{id}/snapshots` |
| `GET /properties/{id}/history` | 刊登詳細頁已有價格歷史 |
| `GET /registry/buildings`、`/unit-types`、`/coverage`、`POST /registry/derivation-rules` | 名冊由 CSV 載入；規則驗證與撤回已可用 |
| `GET /evidence/{id}/dependents`、`POST /evidence:independence`、`GET /source-origins/{id}`、`POST /assessments:reassess` | 內部函式已有，未開 API |

### 3.1 JEV 決策模型（`jev/decide.py`）
| 項目 | 實作 |
|------|------|
| provider | `openai`（`/v1/decisions`）、`openrouter`（`/api/v1/systemone` 或 `/api/alpha/decisions`）、`typesafe`（`/v1/systemone`，只收文字） |
| 題目 | `layout_front_row`（照片）、`floor_band`（照片）、`membership_text`（文字）、`same_dwelling`（文字，可附照片）；`suggest` 依刊登狀態建議 |
| 計分 | S13 ±0.3、S14 −0.075～+0.15、M9m ±0.2、P9m ±0.2；只調整排序或分數，不排除、不確認；照片重複使用（PHOTO_REUSE）不計分 |
| 保護 | 預設關閉；文字、圖片外送分開允許；每次要 `consent: true`；每月預算上限；照片只存雜湊；每次呼叫記錄費用、延遲、錯誤；網址必須 https |
| 評估 | `jev eval 題目檔 [--dry-run]`：答對率、Brier、log loss、校準誤差（ECE） |
| 照片流程（D-115） | 逐張分類 → 只用室內有窗景的照片 → 候選窮舉（S16）＋樓層（S14，只在樓層未揭露時）；照片網址由書籤帶入、勾選後才在記憶體中下載 |
| 真實測試（2026-10-19，OpenRouter） | **文字窮舉 8 題**：Jev 1.14 8／8、OpenAI GPT-6 Luna 6／8（沒有線索時偏向某一戶）；花費 US$0.0004／0.0006。**照片**：20790495（9 樓）7 張照片的分類與人工判讀一致，排除 2 張大廳；樓層判斷不篩選時錯（低 61%）、篩選後對（中 85%）；D2／D5 得 59／41（線索弱，模型沒有硬猜）；8 次呼叫 US$0.0011。題數很少，只能證明流程可用，不能證明準確度 |
| 尚未驗證 | OpenAI 直連 `/v1/decisions` 與 OpenRouter alpha decisions 的格式（目前回 400）；經 OpenRouter 呼叫 OpenAI 模型請用 systemone 格式 |

## 4. 實作中發現並修正的問題
規格問題記在 D-112、D-114（實價登錄循環論證的更正）。程式缺陷（都已加上測試）：

| 問題 | 影響 | 修正 |
|------|------|------|
| `EvidenceCreate` 的 schema 組合不可能成立 | 任何新增證據的請求都不合法 | 拆出 `UserEvidenceFields` |
| 社區歸屬 SQL 欄位名稱模糊 | 任何明寫門牌號的刊登都會當掉 | 指定 `m.record_status` |
| 明寫門牌的樓層沒有用來產生候選 | 「79號12樓」變成資訊不足 | G2 使用門牌樓層 |
| 同屋覆核當掉；社區歸屬覆核、排除候選沒生效 | 無法人工決定 | 補上三種決定 |
| 已處理的配對與任務一直重開 | 同一問題反覆詢問 | 內容沒變就不再開任務 |
| 撤回合併的依賴檢查不完整 | 可能還原出錯誤的群組 | 檢查同一 property 的後續操作 |
| 更正通知沒有送出 | 收不到更正 | `notify` 一併送出 |
| 匯入時每列開一個輪次；新 property 沒計算上架數 | 狀態錯誤 | 修正 |
| 未處理的例外讓伺服器斷線（請求本體是陣列、坪數填文字） | 前端只看到連線失敗 | 全域錯誤處理、型別檢查 |
| 沒有 schema 遷移 | 新增欄位後舊資料庫會出錯 | 自動備份＋補欄位 |
| commit 散在 10 個檔案 | 操作中途失敗留下一半的資料 | 一個操作一個交易 |
| 共用連線的並行讀取 | 前端同時發請求會讀錯（404） | 讀取也排隊 |
| 資料沒變也一直寫新的評估 | 資料庫無意義變大（26 → 154 筆） | 結果簽章相同就沿用 |
| 刊登編號沒跳脫就放進頁面 | XSS | 跳脫 |
| 寫死的預設金鑰、沒有 Host 檢查 | 本機其他程式可用、DNS rebinding | 自動產生金鑰、Host 檢查 |
| 書籤把「熱門社區」當成刊登的社區 | 社區歸屬判錯 | 以「位於○○」為準 |
| 其他：同秒先後、36.115 四捨五入、非 UTF-8 請求、OpenRouter decisions 端點路徑 | — | 修正 |

## 7. 已知限制與需要你決定的事
- **決策模型還沒有用真實模型測過**：等你同意後，先 `jev eval --dry-run` 檢查格式，再用真值題目測答對率與校準。
- **照片權利（Q-034）**：送 591 照片給外部模型屬於自用分析，但仍是把照片傳給第三方；目前靠逐次勾選同意。
- **門牌確認需要獨立佐證**：管委會門牌對照表或現場門牌。官方實價登錄不能佐證戶別→門牌號（D-114）。
- **通知管道（Q-005）**：Email 與 Telegram 都已實作，選一個在 `.env` 設定即可；沒設定時寫入 outbox。
- **左右鏡像（C1／C2、B 棟）**：需要「廚衛在客廳窗的哪一側」與戶別的對照，名冊目前沒有，這一題的模型判斷暫不計分。
- 驗證腳本（文件一致性檢查）仍只在工作階段暫存區，放進 repo（`tools/`）需要你同意。
- 介面沒有登入機制，只能在本機使用。`data/demo.db` 的 DEMO-001、DEMO-002 是模擬資料。
