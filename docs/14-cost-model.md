# 14 成本模型

> 只列假設與費用項目，**不填任何價格**。單價一律是【待查證】；預算是【待確認】（Q-011）。

## 1. 假設（【建議預設】）
| 代號 | 假設 | 值 |
|------|------|----|
| A1 | 部署在既有的本機 Windows 主機（Q-006） | 是 |
| A2 | 每天監控輪次數（Q-004） | 2 |
| A3 | 每輪頁數上限 | 依來源設定（`page_cap`） |
| A4 | 刊登總量 | 【待查證】依試點社區規模 |
| A5 | 每週覆核量上限（Q-023） | 30 筆 |
| A6 | 每筆覆核平均耗時 | 【待查證】在 M0 標註時實測 |
| A7 | 通知管道（Q-005） | Email 或 Telegram |
| A8 | 原始內容保存 | 依權利；最多 90 天 |

## 2. 費用項目
| 類別 | 項目 | 計算方式 | 單價 |
|------|------|----------|------|
| 運算 | 本機電力與硬體折舊 | 運轉時數 × 功耗 × 電價 | 【待查證】 |
| 運算（替代方案） | 雲端 VM 或 Serverless（如果 Q-006 改成雲端） | 規格 × 時數 | 【待查證】 |
| 儲存 | DB 與原始內容 | 刊登數 × 快照數 × 每筆大小；原始內容 × 保存天數 | 本機可忽略；雲端【待查證】 |
| 備份 | 異地備份空間 | 備份大小 × 份數 | 【待查證】 |
| 通知 | SMTP、Telegram、LINE 等 | 每月則數 × 單價（部分可能免費，條款【待查證】） | 【待查證】 |
| 資料取得 | 平台付費方案或授權 API（如果有，Q-024） | 方案費 | 【待查證】 |
| 開放資料 | 政府開放資料 | 通常免費；授權條款【待查證】 | 【待查證】 |
| 人力 | 名冊核對（M0） | V-01～V-07 工時 | 使用者時間 |
| 人力 | 標註（真值） | 樣本數 × 每筆耗時 | 使用者時間 |
| 人力 | 日常覆核 | A5 × A6 × 週數 | 使用者時間 |
| 人力 | 維護 parser（平台改版） | 改版次數 × 修復工時 | 開發者時間 |
| 專業諮詢 | 法律意見（如果需要，與 Q-021 有關） | 次數 | 【待查證】 |
| 人力 | 樂居格局圖人工整理（Q-033） | 戶別數 × 每戶整理時間 | 使用者時間 |
| 人力 | 照片格局人工比對（16 階段 1） | 刊登數 × 每則比對時間 | 使用者時間 |
| 人力 | 照片比對標註（16 階段 2 前置） | ≥ 200 則照片組 × 每則標註時間 | 使用者時間 |
| 運算 | 自動影像辨識推論（16 階段 2，Q-034） | 照片數 × 單次推論成本（本機或雲端 API） | 【待查證】 |
| 開發工具 | AI 輔助開發 | 使用量 | 依使用者既有方案 |

## 3. 敏感度
- 最大的變動來源是**人力**（覆核量、名冊缺口），不是運算。
- 如果改成雲端部署或多使用者，儲存、運算、資安的成本會一起上升，需要重新估算。
