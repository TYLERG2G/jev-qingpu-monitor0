# 18 JEV 使用手冊

> 對象：使用者本人。v0.6（2026-10-18）。JEV 在你的電腦上執行，只綁 127.0.0.1；資料只來自你的人工記錄與官方開放資料。

## 1. JEV 對一個社區能做什麼
JEV 針對一個社區（目前是聯上世界）做三件事，彼此分開判斷：

| 判斷 | 回答的問題 | 依據 |
|------|------------|------|
| ① 社區歸屬 | 這則刊登是不是聯上世界？ | 路段、591 社區編號、標題文字；「近聯上世界」會扣分 |
| ② 戶別與完整門牌 | 是哪一戶、哪一層？完整門牌是幾號幾樓？ | 坪數（自動扣車位）、樓層、房數、朝向、該層戶數；照片判斷（人工或 JEV 決策模型） |
| ③ 同屋辨識 | 不同刊登是不是在賣同一戶？ | 候選交集、坪數、樓層、房數；你的確認 |

再加上**監控**：同一則刊登每次重新匯入，都會比對價格與欄位，產生降價、下架、重新上架等事件，並依你設定的規則通知。

打開 `http://127.0.0.1:8787/`，第一頁「社區總覽」會顯示：
- **各棟各戶**：17 個戶別的位置、門牌號、坪數，以及目前有哪些刊登落在這戶（標籤帶「?」表示是鏡像戶二選一）。
- **缺口與下一步**：依「對門牌準確度的幫助」排序，每一項都可以直接點開相關刊登。
- **開價行情**：依坪型分組的總價範圍與單價中位數（同一戶多則刊登只算一次）。
- **官方實價登錄成交**、**門牌推導規則**的驗證狀態。

## 2. 開始使用
```powershell
cd C:\Users\als14\Projects\jev-qingpu-monitor
$py = "C:\Users\als14\anaconda3\python.exe"
& $py -m jev serve                 # 開啟 http://127.0.0.1:8787/
```
- 第一次啟動會自動產生本機 API 金鑰（存在 `data\api_key.txt`），網頁會自動帶入，不用自己輸入。
- 每次啟動前會自動備份資料庫到 `data\backups\`（保留最近 20 份）；日誌在 `data\logs\jev.log`。
- 設定都在 `.env`（範本 `.env.example`）；`python -m jev config` 可以檢查設定（金鑰會遮住）。

## 3. 日常流程（每週約 10 分鐘）
1. **匯入刊登**：開 `http://127.0.0.1:8787/tools`，把「📥 匯入 JEV」拖到書籤列（只要做一次）。之後在瀏覽器打開 591 的聯上世界刊登，按書籤 → 核對欄位 → 「寫入 JEV」。
   - 新刊登：勾「我確認這是剛上架的新刊登」才會發新刊登通知。
   - 已存在的刊登：記成新觀測；價格變了會產生降價事件。
   - 也可以整理成 CSV（`templates\listing-intake-template.csv`）後執行 `python -m jev cycle 檔案.csv`。
2. **看社區總覽的「缺口與下一步」**：照順序處理。
3. **覆核**：系統縮小到 1–2 戶時會開覆核任務。你可以排除某一戶、標記無法判斷，或附上現場佐證確認門牌。
4. **下架**：在刊登詳細頁按「標記已下架」（手動模式不會自動推定下架）。

## 4. 讓門牌更準的順序
| 順序 | 做什麼 | 效果 |
|------|--------|------|
| 1 | 沒有樓層的刊登用書籤重新匯入 | 頁面有樓層就會從 13–26 個候選縮成 1–2 個 |
| 2 | 鏡像戶（D2／D5、C1／C2 等）：用照片判斷，或請 JEV 判斷窗景（§5） | 2 個候選的排序更明確（不會刪除任何一個） |
| 3 | 取得管委會門牌對照表或現場門牌照片，到覆核頁驗證「戶別→門牌號」 | 驗證後，坪數＋樓層能縮到單一戶的刊登，系統可以自行確認門牌（K1–K5） |
| 4 | 下載多季官方實價登錄，`python -m jev lvr 檔案.zip --import` | 檢查同一號各樓層坪數是否一致（驗證推導規則） |
| 5 | 看屋時拍下門牌、記下仲介出示的刊登編號，在覆核頁「以現場佐證確認」 | 門牌正式確認（H1–H6） |

> 為什麼目前 0 則門牌已確認：591 不公開門牌，而「戶別→門牌號」對照表只來自 591／樂居的示意圖（疑似同源），沒有獨立佐證。JEV 依規則不會自行宣稱確認；要有第 3 或第 5 項的佐證。

## 5. JEV 決策模型（D-020）
JEV 可以把「看得到的事實」交給決策模型判斷，例如：
- **窗景是否面對高鐵南路** → 分辨前排（上排）與後排（下排）的鏡像戶，例如 D2 與 D5。
- **廚房在客廳窗的左側或右側** → 分辨左右鏡像（C1／C2、B 棟）。要先在 `docs\research\unit-feature-map.csv` 補上各戶的 `kitchen_side`（可從樂居平面圖判讀），目前全部是 unknown，所以這一題暫不計分。
- **從窗景判斷樓層高低** → 樓層沒揭露的刊登，把可能的樓層排序。
- **文字描述是不是就在聯上世界** → 社區歸屬未定的刊登。
- **兩則刊登是不是同一戶** → 同屋配對的參考。

**模型的答案只會調整排序**（最多 ±0.3），不會刪除候選，也不會讓門牌變成已確認；答案可以隨時撤回。同一張照片出現在不同刊登時，這張照片的判斷不計分。

### 5.1 設定（以 OpenRouter 為例）
在 `.env`：
```
JEV_DECISION_PROVIDER=openrouter
OPENROUTER_API_KEY=你的金鑰
OPENROUTER_DECISION_MODEL=typesafe/jev-1.14        # 或 openai/gpt-6-luna-decisions（搭配 OPENROUTER_WIRE_FORMAT=decisions）
JEV_DECISION_ALLOW_TEXT=true
JEV_DECISION_ALLOW_IMAGES=true                     # 要送照片才設 true
JEV_DECISION_MONTHLY_BUDGET_USD=1                  # 每月上限，達到就停止呼叫
```
改完重新啟動 `python -m jev serve`。社區總覽會顯示「JEV 決策模型：openrouter · …」。

### 5.2 使用
- **最快的方式**：用書籤匯入 591 刊登時，表單下方會列出這則刊登的照片 → 勾選看得到窗外的室內照片（最多 6 張）→ 寫入 → 刊登詳細頁的「③ JEV 判斷」會帶著這些照片 → 勾選同意 →「請 JEV 判斷」。照片由 JEV 在記憶體中下載，判斷完就丟，不會保存。
- JEV 會先把每張照片分類（室內有窗景、室內無窗景、大廳公設、外觀、平面圖），只用有窗景的室內照片；大廳照片會讓樓層判斷出錯（實測：不篩選時把 9 樓判成低樓層 61%，篩選後中樓層 85%）。
- 主要題目是「照片比較像哪一戶」：把規則篩出的候選戶別列成選項讓 JEV 選（例如 D2 前排、D5 後排）。照片看不出差別時，JEV 會回答接近均分，排序就幾乎不變。
- 也可以自己選照片上傳（在瀏覽器先縮小）。每則刊登約 6–8 次呼叫，實測約 US$0.001。
- 同屋：覆核頁的同屋任務 →「請 JEV 判斷…」。
- 命令列：`python -m jev ask 3 --image 窗景.jpg --yes`；`python -m jev decisions` 看花費與呼叫紀錄。

### 5.3 先評估再相信
1. 準備有正確答案的題目：複製 `templates\eval-template.jsonl` 到 `data\eval\`，照片放 `data\eval\photos\`（都不會進 git）。正確答案要是你**確定**的（現場看過、管委會資料）。
2. `python -m jev eval data\eval\我的題目.jsonl --dry-run`：只產生請求內容讓你檢查，不連網、不花錢。
3. 拿掉 `--dry-run` 真的測：報告在 `data\eval\`，包括答對率、Brier、校準誤差（模型說 80% 時是否真的約八成答對）。
4. 題數至少 20–30 題再下結論；答對率或校準不好，就不要依賴模型的排序。

## 6. 通知
- 「事件與通知」頁可以新增、修改、停用規則：事件類型、總價上限、降幅至少幾 %、至少幾房、至少幾坪、管道（Email 或 Telegram）。
- 管道沒有設定時（Q-005），通知寫入資料庫旁的 `outbox` 資料夾。
- Email：在 `.env` 填 `JEV_SMTP_*`；Telegram：填 `JEV_TELEGRAM_BOT_TOKEN`、`JEV_TELEGRAM_CHAT_ID`。
- 第一次建庫（INITIAL）不會發任何通知；同一事件不會重複通知；同屋群組改變時會發更正通知。

## 7. 資料與隱私
| 會保存 | 不會保存 |
|--------|----------|
| 刊登的房屋欄位、價格、網址、仲介公司名稱 | 仲介姓名、電話等個人資料 |
| 照片的雜湊與大小（只在你送給模型時） | 照片本身、原始頁面 |
| 模型的答案、模型名稱、每次呼叫的費用與延遲 | 送出的請求內容（只存雜湊）、金鑰 |
| 你的覆核決定與佐證描述 | — |

- 送到外部模型的只有房屋欄位與你選的照片，而且每次都要你勾選同意。
- 資料庫 `data\jev.db`、備份、日誌、金鑰、`.env` 都被 git 排除。

## 8. 常見問題
- **刊登顯示「無法判定」**：只有社區名稱與路段、沒有 591 社區編號。重新匯入並補上 `591:9488`，或在覆核頁確認。
- **候選有 13 或 26 個**：樓層沒揭露。用書籤重匯（頁面可能有樓層），或請 JEV 判斷樓層高低。
- **鏡像戶永遠是 2 個候選**：這是正確的。坪數相同時，只有照片、現場或對照表能分辨。
- **網頁顯示錯誤**：看 `data\logs\jev.log`；所有錯誤都會記錄。
