# 03 資料來源與權利

> 本階段**沒有連線到任何來源**。所有條款、robots、授權方式都是【待查證】（Q-003）。本文件提供來源清單與權利紀錄的框架，不代表任何來源允許或禁止某種用途。

## 2. 權利紀錄（每個來源，每種資料類型）
每個 `source` 都要分開記錄四種權利（`source.rights`），值為 `ALLOWED`、`RESTRICTED`（有條件）、`PROHIBITED`、`UNKNOWN`：

| 權利 | 問題 | 影響 |
|------|------|------|
| `acquire` 取得 | 可不可以存取或下載？用什麼方式（瀏覽、API、匯出）？ | 決定能不能擷取 |
| `store` 保存 | 可不可以保存原始內容？保存多久？ | 決定 `source_document.raw_ref` 能不能保留、保留多久 |
| `image_use` 圖片利用 | 平面圖、照片可不可以下載、轉錄、拿來比對？ | 決定圖資證據的形式（只存網址＋人工轉錄，或保存圖片） |
| `republish` 再發布 | 可不可以在通知或匯出中重現內容？ | 決定通知與匯出能包含哪些欄位 |

預設值全部是 `UNKNOWN`。UNKNOWN 時的保守處理（【建議預設】）：
- 取得：只做使用者人工瀏覽後的人工記錄。
- 保存：只存結構化欄位、短摘錄（≤ 200 字，遮罩個資）、內容雜湊；不存原始頁面。
- 圖片：只存網址與人工轉錄，不下載圖片。
- 再發布：通知只放必要欄位與原刊登網址，不轉載描述或圖片。

## 3. 存取方式分類
| `access_method` | 說明 | 是否允許 |
|-----------------|------|----------|
| `PUBLIC_WEB` | 不需登入的公開頁面 | 要先通過權利檢查與頻率限制 |
| `AUTHORIZED_API` | 官方 API 或授權資料介面（可能需要金鑰或登入驗證） | **允許**，前提是依授權條款使用（Q-024） |
| `AUTHORIZED_ACCOUNT` | 使用者本人帳號、在條款允許範圍內的存取 | 只限人工或條款明確允許的自動化；不得共用帳號 |
| `MANUAL_ONLY` | 只能由使用者人工記錄 | 允許 |
| `NOT_ALLOWED` | 條款禁止，或技術上只能靠繞過限制才能取得 | 不使用 |

**需要驗證不等於禁止**：依授權使用 API 或會員功能，與「繞過網站存取限制」是兩件不同的事。以下行為一律禁止：破解或繞過 CAPTCHA、偽造身分或輪換 IP 規避封鎖、違反條款的自動化登入、存取未授權的路徑。

## 4. 人工記錄並非零風險
人工匯入一樣涉及取得、保存、圖片利用與再發布的權利問題（例如：把整段刊登描述或平面圖貼進系統保存）。因此：
- `SRC-MANUAL` 的每一筆證據，都要記錄**原始出處**（`origin_source_code`、網址），並沿用原始出處的權利設定。
- 人工轉錄的圖資只存轉錄結果與出處，不保存圖片本身（除非 `image_use` 與 `store` 允許）。

## 5. 啟用自動擷取的條件（ADR-003）
以下全部成立，才能把 `auto_fetch_enabled` 設為 true：
1. `rights.acquire` 是 `ALLOWED`，或是允許自動化的 `RESTRICTED`。
2. `access_method` 是 `PUBLIC_WEB` 或 `AUTHORIZED_API`。
3. robots 規則允許目標路徑（`PUBLIC_WEB` 時）。
4. 已設定頻率上限（【建議預設】每次請求間隔 ≥ 10 秒、單一連線）。
5. 已記錄檢查人、檢查日期、條款網址與相關條文摘要；每 6 個月覆核一次。
6. 已定義 `canonical_scope`（列表查詢範圍）與指紋，供完整輪次判定使用（07）。

## 6. 法規面（【待查證】，不是法律意見）
- 個資：刊登者姓名、電話不保存（Q-015）；摘錄要先遮罩。
- 著作權：照片、平面圖、描述文字可能受保護，依 `image_use`、`republish` 處理。
- 違反存取限制可能有法律風險，因此採取 §3 的禁止清單。
- 是否需要專業法律意見：【待確認】（與 Q-021 商業使用一起決定）。
